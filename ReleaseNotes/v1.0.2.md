iBestSpeech 1.0.2
===============

Three silences fixed, all three of them in the engine rather than worked around
in the text handed to it. **This is the sideloadable build** — unsigned and with
no App Group entitlement, so iLoader, AltStore, SideStore or Sideloadly can
re-sign it with your own Apple ID.

## Clock times

"5:19 PM" was silent on every build. So was "3:20 PM", "12:00" and "14:30". A
colon between two digits gets a state of its own in the engine's transition
table, so a time arrives at the number reader as a single token, `8:00`, which
rejected anything that was not a digit — and what followed fell to a path that
never reached the machine. Every run either side of the colon is now read as a
number, with nothing said between them.

That "nothing between them" is the point. The engine's own group separator is a
*spoken word*; emitting it makes "5:19" say "five dash nineteen". Reading the two
runs back to back is what makes "5:19 PM" say "five nineteen P M" — byte for byte
identical to spelling the words out, and verified so on nineteen of the twenty
builds.

## A stop written straight against a digit

`Read.6:23 PM` is how an accessibility value often reads, and it produced no
audio at all, on every build. The stop restarts the token at itself, so the
number reader was handed the run `[".6"]`, rejected it, and left the state
machine on the same token until its guard expired.

This is also why it took so long to find: a space after the stop hides it
*completely*, because the space is eaten and the token restarts on the digit.
`Read. 6:23 PM` always worked. Only the joined form was silent.

With the tokeniser's trace on, the guard turned one input into three million
repetitions of a single line. Leading non-digits are now skipped, so the digits
after them are read: `Read.6- 23 PM` and `Read. 6- 23 PM` now produce the same
words.

## 1998: minutes that start with a zero

The 1998 English module's digit-name, tens and teens tables were addressed **four
bytes low**. Every digit resolved one slot into the next name — a single digit
read the *following* digit's name, and a two-digit run of 10 or less ran off the
end of the table entirely. That is the old "5:07 reads as a long sequence" fault,
and it was never about the leading zero: `5:10` failed the same way.

All hundred values 00–99 now read. The other five 1998 languages are generated
from that same map, address for address, so they are corrected by the same
change. 1995 and 2006 are untouched by it.

## Text the engine can actually read

The engine is a single-byte code page. Anything outside ASCII is read as one of
its glyphs and **spliced onto the word in front of it** — which is where the
"oz" before "Read" came from: iOS wraps accessibility values in bidi marks, and
the mark was being spoken as part of the preceding word. Some of those characters
did not add a phoneme, they produced **zero samples**: a whole utterance silently
lost to one invisible byte.

Non-ASCII text is now folded before it reaches the engine. Bidi marks, zero-width
spaces, soft hyphens and the byte order mark are removed; non-breaking spaces
become ordinary ones; typographic punctuation — curly quotes, en and em dashes,
the ellipsis — becomes its ASCII equivalent; and accented letters are decomposed
with the diacritics dropped.

**One trade-off, stated plainly:** folding drops accents. Where a build genuinely
speaks them — 2006 German really does say "über" with the umlaut — this release
gives up the accent to gain speech. It is a choice, not a free improvement.

## A back door closed

`~` is the engine's command character, and it was being obeyed. `Read ~x] 6:23 PM`
switched the engine into dictionary mode and changed the reading of the whole
utterance. A plain `~` in text — a path, a tilde in a document — reached that
parser. It is now neutralised to a space.

## Verified rather than assumed

`iOSProject/engine_tests.py` covers all three engine faults plus the text that
already worked, and a GitHub Actions Mac runner builds the engine, the
XCFramework, the Swift layers and the app on every push. The workflow also
reverts the engine patch and requires the tests to **fail**, so a test that has
quietly stopped exercising anything cannot sit there passing.

## Installing

Re-sign with your own Apple ID. A free Apple ID limits you to three apps with a
seven-day expiry, so plan accordingly.

The App Group is stripped from this build: a free account cannot obtain one, and
a profile granting it needs a paid account. Nothing in the Swift reads it — the
voice list comes from the engine's own static build table — but that is an
assumption and no run has confirmed the app works without it. If the voices do
not appear in Settings after sideloading, that is the first suspect.
