# iBestSpeech 1.0.4

Emoji and other characters the engine cannot read are now spoken as their
names, the terms it mispronounces are read from a dictionary, and a voice
follows the language of the text it is given.

## Emoji were not silent, they were nonsense

A lone check mark (`✓`) produced 37,691 samples and six word tokens on 2006ENG.
`©` and `®` produced a sample count with **no word tokens at all**. The engine
reads one byte per character, so an emoji is a code-page glyph: not silence, and
not anything a listener can use.

Characters the engine has no reading for are now replaced with the words for
them, from the Unicode Common Locale Data Repository — the same source and the
same `tts` annotation NVDA turns into its `cldr.dic` symbol dictionaries. They
are spoken in the language of the voice: `😀` is "grinning face" in English and
"grinsendes Gesicht" in German. 3,870 entries in English, 29,982 across the
thirteen locales.

Two things in the raw data could not be used as it comes, both measured:

- **CLDR writes its descriptions with `:` and `,`** — 2,784 entries carry one.
  A comma ends the text on every 2006 build, and this description is the whole
  utterance, so "family: man, woman, girl" would say "family" and stop.
- **CLDR also annotates 30 punctuation characters** (`!`, `,`, `.`, `:`, `~`).
  Those are characters the engine already reads, and substituting them would
  rewrite the punctuation of ordinary text. Only characters outside ASCII are
  replaced, which is the line NVDA draws too: its punctuation symbols speak only
  at the highest symbol level, while emoji speak at every level.

Emoji that are one character to Swift but several code points — the heart with
its variation selector, skin-tone sequences, flags — are looked up by their base
form, because that is how CLDR keys them.

## Terms the engine gets wrong are now in a dictionary

The engine reads an unknown compound as one word: `FaceTime`'s token stream is
**identical to `facetime`**, so it comes out as one odd word rather than "face
time". `iPhone`, `macOS`, `AirDrop` and `SQL` go the same way.

160 terms — Apple product names, networking and file-format initialisms, and
modern usage the 1990s lexicon has no entry for — are now replaced before the
engine sees them.

Every entry was measured against the built engine first, because an entry whose
term the engine already reads correctly costs a lookup and changes nothing, and
an entry whose replacement is silent trades a mispronunciation for no sound at
all. Twelve such entries were found and removed. Matching is case-sensitive and
whole-word, which is what keeps `AI` from rewriting the same letters inside a
French word.

## A voice follows the language of the text

The engine keeps one voice per build, so a voice could previously only speak the
one language it was made for. Each run of text is now checked, and text that is
clearly in another language is spoken with that language's build.

Script is decisive where it applies: Cyrillic, Greek, Arabic, Hebrew and kana
each belong to exactly one build, so a single such character settles it. For the
eight languages that share the Latin alphabet, the text is scored against
function words — "the", "der", "le" — and needs both a floor and a clear win
over the runner-up.

It **declines far more often than it guesses**, and that is the point: a wrong
switch changes the voice the user hears, which is worse than no switch. A single
word like "Hallo" is in several of these languages, so it never switches a
voice; a word three languages share claims nothing at all. If the language's
build is not in the app bundle, the piece is spoken with the voice you asked
for rather than dropped.

## Under the hood

- The generated tables ship as one string per language, decoded on first use.
  As a single dictionary literal of 31,331 entries, Swift type-checked it as one
  expression and this project's CI job was cancelled at its timeout.
- The pronunciation pass compiles its patterns once and skips a term that is not
  in the text before running any pattern match.
- CI now compiles the tables and the language detector with their tests, and
  fails when the generated tables no longer match `tools/dictionary.txt`.
