# iBestSpeech 1.0.5

Two faults reported from use, both reproduced on the engine and both fixed.

## "FAQ" was read as "F I Q"

The pronunciation dictionary said to say it "eff ay cue" — and this engine reads
**"ay" as the word "aye"**, not as the letter A. The A came out as an I.

The entry was also doing harm that was never needed. This engine **already spells
an all-caps run letter by letter**: the audio for `FAQ` is byte-for-byte the same
as for `F A Q`. Adding an entry to something the engine already reads correctly
can only make it worse, and this one did.

That turned out to be true of most of the acronym section. Measured on the
engine, **48 of the 63 acronym entries were unnecessary** — PDF, URL, CPU, HTTP,
SQL, USB, HTML, JSON, XML, GIF, ZIP and the rest are all already read correctly.
The dictionary is down from 160 entries to 111, and every one that remains is
verified to change the sound, none is silent, and none is a no-op.

For the ones that do need help, the replacement is now **the letters themselves**
rather than a phonetic spelling. A phonetic name is unsafe in general: "cue" and
"eye" and "pee" happen to sound exactly like their letters, but A, E, N, R, U and
W are read as words. Two entries stay spelled as words on purpose — ASCII ("ass
key") and OSHA ("oh shah") — because that is how they are said.

## "No Updates Available" was read as Spanish

"No" is a Spanish word, and nothing in three words outvoted it. The same happened
to "No SIM Card" and "No Internet Connection" — the "No <Noun> <Adjective>" shape,
which is everywhere in an operating system.

The detector now has a list of words that exist in **exactly one** of these
languages. One of those is proof, the way a Cyrillic letter is: "Available" cannot
be anything but English. Exclusivity is computed rather than assumed, because the
Romance languages share a great deal — "disponible" is French *and* Spanish — and
a word that two lists share is proof of neither.

**A voice switches far less often now, and that is the point.** 26 real interface
strings are asserted never to be read as another language: "No Items", "Do Not
Disturb", "Screen Time", "Face ID & Passcode", "Software Update", "Airplane Mode"
and the rest.

## Verified

- Engine regression tests **78/78** on a fresh clone of the pinned engine with the
  patch applied, and confirmed to fail without it.
- The oracle of the original Keynote DLLs' answers: **4906 identical, 0
  differing**.
- App-side Swift tests **121/121**; language detection **51/51** (was 24).
- Dictionary, judged on the engine's own audio on all three English builds:
  **111/111 change the sound, 0 silent, 0 no-ops**.
- CI green, including the Xcode app build and the XCFramework.
