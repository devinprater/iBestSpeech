# Pronunciation dictionary for the Keynote Gold builds.
#
# Plain text, tab-separated: the word as typed, then how it should be said.
# Blank lines and lines starting with '#' are ignored.
#
# Matching is CASE-SENSITIVE and whole-word, which is what keeps these safe:
# "AI" is fixed while the "ai" inside a French word is left alone. Add a term
# twice if both spellings need it.
#
# Only terms the engine actually gets wrong belong here. Every entry below was
# measured against the built library first -- the engine reads "FaceTime" as one
# unknown word (its token stream is identical to "facetime"), not as "face time".
# An entry that matches what the engine already says is a wasted lookup, so check
# before adding: see tools/build_tables.py --check.
#
# Two entries spell a word rather than the letters, on purpose: ASCII and
# OSHA are said as words ("ass key", "oh shah"), not letter by letter.
# Everything else that spells letters uses the LETTERS THEMSELVES, spaced.
# A phonetic name is not safe here: this engine reads "ay" as the word
# "aye", not as the letter A, which is how "FAQ" once came out "F I Q".
# An all-caps run the engine already spells needs no entry at all -- it
# reads "PDF" and "URL" letter by letter on its own.

# --- Two-letter acronym plurals: the engine holds "pcs" as a WORD ---
#
# Measured: the engine's lexicon contains "pcs" as an ordinary word, so a
# two-letter caps run followed by "s" is looked up as that word instead of being
# spelled. "PCs" is byte-identical to lowercase "pcs" (9244 samples on 2006ENG,
# 5877 on 1995) and differs from the spelled form ("P C S", 13071) -- that is why
# "PCs" is heard as "pieces". The collision is with the word, not a misspelling
# of the letters.
#
# A 3+ letter run is unaffected: "CPUs", "APIs", "IDs" and "USBs" already spell
# letter by letter on their own, because no such word exists to be looked up.
# Measured over all 676 two-letter runs, exactly the 16 below glom; every other
# one spells correctly.
#
# ⛔ Adding a space before the "s" of a term that already works CHANGES ITS AUDIO
# (measured on all three English builds: CDs, TVs, IDs, MPs, IOs, KBs, GPUs, ...),
# so this is per-term and cannot be a general rule.
#
# The replacement is the two letter names said as ONE WORD, which is how a person
# says a plural acronym. The engine renders "pea seas" as two words, so the entry
# has to join them: name1 + the doubled onset of name2 + name2 + s. For PCs that is
# "pea" + "s" + "seas" = "peasseas", which the engine reads as ONE word whose phone
# sequence is exactly "pea seas" (16 23 0D 23 49) on 1995, 1998ENG and 2006ENG and
# on the real dll_eng.dll / b32_tts.dll. A hyphen between the names is NOT the fix:
# measured byte-identical to the two-word form, i.e. still two words.
#
# Five of the sixteen have such a one-word match and use it. The rest keep the
# letters spaced ("H As"), which spells the letters correctly -- the bug was the
# glommed lexicon lookup, not the letters -- but no one-word join reproduced their
# letter-name phone sequence exactly, and a wrong join is worse than a correct
# two-word reading.
#
# "MRs" is included because the native form is SILENT (0 samples) on 2006ENG.
